---

# 🥇 第一阶段：A 用 Spring Boot 自带功能接 TCP

Spring Boot 本身不提供现成 TCP Server，但你可以：

* 用 java.net.ServerSocket
* 或 Spring Integration TCP

这一步的价值是什么？

不是性能。
是理解：

* Bean 生命周期
* 线程模型
* 项目分层
* 配置管理
* 日志体系

你会学到：

```
TCP Server 是一个 Spring Bean
它如何启动
如何优雅关闭
如何和 Service 层解耦
```

这一步是“架构意识入门”。

对运维来说，这非常关键。

---

# 🥈 第二阶段：B 用 Netty 写 TCP Server

等你理解：

* 什么是粘包
* 什么是拆包
* 什么是 Reactor 模型

再上 Netty。

Netty 不是为了炫技。

它是为了理解：

* 高并发
* 事件驱动
* IO 线程模型
* Channel Pipeline

这一步你会真正理解：

“服务是如何撑住 1 万设备的”。

这对未来做架构，价值巨大。

---

# 🥉 第三阶段：C 单独做 Gateway

当你开始问：

* TCP 服务是不是应该和业务解耦？
* 设备层是否应该独立部署？
* 是否要做协议转换层？

你就进入架构阶段了。

那时你会拆成：

```
device-gateway (Netty)
attendance-service (Spring Boot)
```

再往后可能是：

* Kafka
* 消息队列
* 异步解耦

那已经是“企业级演进”。

# 🥇 第一阶段：单体闭环（理解系统生命线）

> 目标：跑通完整业务链路
> 核心能力：分层 + 数据流 + 线程模型

### 架构形态

```text
device (TCP)
   ↓
Spring Boot
   ├── tcp-server (ServerSocket)
   ├── raw-service
   ├── parse-service
   ├── attendance-service
   └── controller (HTTP)
         ↓
       MySQL
```

技术栈：

* Spring Boot 3.x
* MySQL 8
* 本地部署
* 单体 jar

你要搞懂的不是代码，而是：

1. 数据如何从 TCP 流进来
2. 为什么要先落 raw 表
3. 解析失败如何回滚
4. 线程如何影响并发
5. 日志如何定位问题

这一阶段，你会真正理解：

“系统不是接口，是数据流动。”

这是地基。

---

# 🥈 第二阶段：模块化拆分（开始有架构意识）

> 目标：解耦 + 可扩展
> 核心能力：边界划分 + 服务职责

### 架构形态

```text
device
   ↓
device-gateway (Netty)
   ↓
attendance-service (Spring Boot)
   ↓
MySQL
   ↓
REST API
   ↓
Vue 前端
```

新增：

* Netty
* 模块拆分
* 独立部署
* Docker Compose

你开始问：

* TCP 服务为什么要独立？
* 设备层能不能水平扩展？
* 业务层是否无状态？

你会学到：

* 端口隔离
* 容器化
* 配置中心
* 日志分流

这一步开始像“工程系统”。

---

# 🥉 第三阶段：企业级演进（架构维度）

> 目标：高并发 + 高可用 + 可观测
> 核心能力：系统治理

### 架构形态

```text
device
   ↓
device-gateway 集群
   ↓
Kafka
   ↓
attendance-service 集群
   ↓
MySQL 主从
   ↓
Redis
   ↓
API Gateway
   ↓
前端
```

加入：

* Kafka（削峰填谷）
* Redis（缓存）
* 主从数据库
* 监控体系
* CI/CD

这时候你开始关心：

* 峰值 1 万设备怎么办？
* 数据丢了如何补偿？
* 服务宕机如何自动恢复？
* 如何灰度发布？

这就是架构师视角。
