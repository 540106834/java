你现在这套查询 API，已经像一辆能跑的列车 
但铁轨远不止两条。查询系统一旦打开，数据的宇宙就会开始发光。

我们来看看还能扩展哪些“观察窗口”。

---

# 一、围绕“班级维度”的查询

### 1️ 查询班级当日汇总

```
GET /api/attendance/summary?class_id=1&date=2026-02-25
```

返回：

```json
{
  "totalStudents": 45,
  "inTotal": 43,
  "outTotal": 42,
  "absentCount": 2
}
```

用途：

* 班主任快速看出勤率
* 大屏统计展示
* 异常提醒

---

### 2️ 查询某班某月统计

```
GET /api/attendance/monthly?class_id=1&month=2026-02
```

返回每天统计数组：

```json
[
  { "date": "2026-02-01", "inTotal": 44 },
  { "date": "2026-02-02", "inTotal": 42 }
]
```

这一步就能接入：

*  Grafana
* 数据趋势图
* 异常波动分析

---

# 二、围绕“学生维度”的查询

### 3️ 查询某学生历史记录

```
GET /api/student/attendance?student_id=1001
```

返回：

```json
[
  { "date": "2026-02-25", "inCount": 1, "outCount": 1 },
  { "date": "2026-02-26", "inCount": 0, "outCount": 0 }
]
```

用途：

* 家长端查询
* 个体异常分析
* 数据血缘追踪

---

### 4️ 查询迟到学生列表

如果你之前定义：

```
check_type
0 = 进校
1 = 出校
2 = 迟到
```

可以做：

```
GET /api/attendance/late?class_id=1&date=2026-02-25
```

这就成了“纪律雷达” 

---

# 三、围绕“设备维度”的查询

你的表里有：

```
device_sn
```

可以加：

### 5️ 设备打卡量统计

```
GET /api/device/stats?date=2026-02-25
```

返回：

```json
[
  { "deviceSn": "GATE01", "count": 1320 },
  { "deviceSn": "GATE02", "count": 1188 }
]
```

这能判断：

* 某闸机是否异常
* 某设备是否断连
* 设备负载是否均衡

---

# 四、异常与运维查询（非常专业）

### 6️ 查询重复打卡

一天内同一学生打卡超过2次：

```
GET /api/attendance/abnormal?date=2026-02-25
```

这属于数据质量控制。

---

### 7️ 查询未绑定卡的学生

如果 `student_card` 没有记录：

```
GET /api/student/no-card
```

这能帮教务提前处理问题。

# 六、未来可以进阶的查询能力

###  时间区间统计

```
GET /api/attendance/range?class_id=1&start=2026-02-01&end=2026-02-28
```

###  出勤率计算

在 SQL 中直接算百分比：

```
出勤率 = 实际到校人数 / 班级总人数
```
