# **完整的渐进式考勤系统架构说明**
从最基础的 MVP 单体架构，到未来可扩展的微服务和 Docker 化架构，按阶段清晰说明模块、数据流和技术点。

# **渐进式考勤系统架构说明**

## **阶段 0 – 单体 MVP 架构**

```
考勤设备
     │ 上传报文
     ▼
+-------------------+
| Parser 服务       |
| (解析报文)        |
+-------------------+
     │ 写入
     ▼
+-------------------+
| MySQL 数据库      |
+-------------------+
     │ API 查询
     ▼
+-------------------+
| 后端 API 服务     |
| (Spring Boot)     |
+-------------------+
     │
     ▼
+-------------------+
| 前端查询页面      |
| (HTML/JS 或 Vue)  |
+-------------------+
```

### **特点**

* Parser 直接写入 MySQL
* 后端 API 查询数据库提供前端数据
* 前端用原生 HTML/JS 或 Vue 3 展示表格
* MVP 速度快，学习成本低

### **核心知识点**

1. SQL 聚合查询
2. Java/Spring Boot 后端开发
3. HTML + CSS + JS 前端基础
4. 数据流理解：Parser → DB → API → 前端

---

## **阶段 1 – 单体分层 / 异步架构**

```
考勤设备
     │ 上传报文
     ▼
+-------------------+
| Parser 服务       |
| (解析报文)        |
+-------------------+
     │ 发消息
     ▼
+-------------------+
| 消息队列 (Kafka)  |
+-------------------+
     │ 消费
     ▼
+-------------------+
| 消费服务 / Worker |
| (写入 MySQL)      |
+-------------------+
     │
     ▼
+-------------------+
| MySQL 数据库      |
+-------------------+
     │ API 查询
     ▼
+-------------------+
| 后端 API 服务     |
+-------------------+
     │
     ▼
+-------------------+
| 前端查询页面      |
+-------------------+
```

### **特点**

* Parser 不直接写数据库，通过消息队列解耦
* 消费服务独立处理写入，可横向扩展
* 后端 API 查询逻辑不变，前端调用也不变
* 支持未来添加高并发设备、多消费者

### **核心知识点**

1. 消息队列 Kafka / RabbitMQ 使用
2. 异步处理和解耦设计
3. 多线程 / Worker 消费处理
4. 架构演进理解：单体 → 异步 → 微服务

---

## **阶段 2 – 完整微服务 + Docker 化**

```
+--------------------+           +---------------------+
| Frontend           | <-------> | Backend API         |
| (Vue 3 / HTML/JS)  |           | (Spring Boot)       |
+--------------------+           +---------------------+
        |                                  |
        | fetch / axios                    |
        ▼                                  ▼
+--------------------+           +---------------------+
| 消费服务 / Worker   | <-------> | MySQL 数据库       |
| (解析消息写入 DB)   |           |                     |
+--------------------+           +---------------------+
        ^
        | 消息
        ▼
+--------------------+
| Parser 服务         |
| (解析设备报文)       |
+--------------------+
        ^
        | 上传报文
        ▼
   考勤设备
        |
        ▼
+--------------------+
| 消息队列 Kafka      |
+--------------------+
```

### **特点**

* 每个模块独立部署 Docker 镜像
* 高并发设备上传 → 消息队列 → 多消费者写入数据库
* 后端 API 独立部署，可扩展多租户
* 前端静态资源单独容器，调用 API

### **核心知识点**

1. 微服务拆分与模块化
2. Docker 镜像打包和部署
3. 高可用 / 可扩展架构设计
4. 消息队列异步处理
5. 前后端独立开发

---

## **阶段演进总结**

| 阶段   | 架构特点         | 学习重点                  | 部署复杂度 |
| ---- | ------------ | --------------------- | ----- |
| 阶段 0 | 单体 MVP       | SQL + API + HTML/JS   | 低     |
| 阶段 1 | 单体 + 消息队列    | 异步处理、Kafka / RabbitMQ | 中     |
| 阶段 2 | 微服务 + Docker | 微服务拆分、容器化、高可用         | 高     |

 **策略建议**：

* **先做阶段 0**：MVP 跑通，快速验证数据流
* **阶段 1**：添加消息队列，理解异步处理
* **阶段 2**：微服务化 + Docker 部署，面向生产环境
