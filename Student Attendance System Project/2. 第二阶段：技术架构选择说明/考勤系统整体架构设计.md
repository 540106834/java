# 一、系统目标定义（第一步必须做）

###  系统核心目标

实现一个学校考勤管理系统，支持：

1. 学生管理
2. 卡片绑定
3. 刷卡生成考勤
4. 查询统计
5. 管理后台操作

---

# 二、整体架构分层

采用经典三层架构：

```
浏览器（前端）
        ↓
API 服务（后端）
        ↓
数据库（MySQL）
```

---

## 1️ 前端层（Browser）

作用：

* 页面展示
* 表单录入
* 调接口
* 展示统计图表

技术：

* HTML / CSS / JS
* 或 Vue / React（后期）

---

## 2️ 后端层（API 服务）

作用：

* 处理业务逻辑
* 权限控制
* 数据校验
* 生成统计数据

技术（你现在的栈）：

* Spring Boot
* JDBC / JPA

---

## 3️ 数据层（MySQL）

存储：

* 学生
* 卡
* 班级
* 考勤记录
* 用户

---

# 三、核心模块拆分（非常关键）

一个系统不等于一堆接口。

我们要模块化。

---

##  模块 1：用户系统

表：

```
user
role
user_role
```

作用：

* 登录
* 权限控制
* JWT 或 Session

---

##  模块 2：班级管理

表：

```
school_class
```

接口：

```
GET /classes
POST /classes
```

---

##  模块 3：学生管理

你已经设计：

```
student
```

接口：

```
GET /students
POST /students
PUT /students/{id}
DELETE /students/{id}
```

---

##  模块 4：卡片管理

你已经设计：

```
student_card
```

功能：

* 绑定
* 解绑
* 查看历史卡

---

##  模块 5：考勤记录（核心）

新增表：

```sql
CREATE TABLE attendance (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    student_id BIGINT NOT NULL,
    card_no VARCHAR(32) NOT NULL,
    check_time DATETIME(3) NOT NULL,
    type TINYINT NOT NULL, -- 1=进校 2=离校
    FOREIGN KEY (student_id) REFERENCES student(id),
    INDEX idx_student_time (student_id, check_time)
);
```

# 四、核心业务链路（必须画清楚）

刷卡流程：

```
设备刷卡
      ↓
POST /api/checkin
      ↓
根据 card_no 查 student_card
      ↓
查 student
      ↓
写入 attendance
      ↓
返回成功
```

这个流程就是系统核心。

---

# 五、接口分层设计

不要把 Controller 写成一坨。

标准结构：

```
controller
service
repository
```

例如：

```
AttendanceController
AttendanceService
AttendanceRepository
```

职责分离：

* Controller：接收请求
* Service：业务逻辑
* Repository：SQL
